1 · The one sentence people should leave with

Everything else hangs off this. For a clinical audience, three ideas at most.

A chatbot answers.
An agent goes and looks.

A model in a loop with tools. It decides what to read next, reads it, and repeats until it can answer. (Phyllis's slot owns this idea; Bruno's slot shows what's inside it.)

The rules are written in plain English, by clinicians.

Instructions and skills are documents. In our study the most important "code" is the clinical definition of each fact, the same text the human annotators followed. Clinicians can write, read and audit it.

Trust comes from showing its work.

Every answer comes with the quote it came from, and a human checks where machines disagree. (Lovedeep's slot owns this idea.)

2 · One patient through the whole hour

A single synthetic patient whose chart every speaker uses. The question the agent has to answer is the quality-measure question from our study, and it's one every cardiologist already recognises:

"Is this a gap in guideline-directed therapy, or is there a documented reason?"
Mrs. Rosa Delgado · 71 · synthetic patient
Admitted for decompensated HF, discharged 9/2/2026

Structured med list: lisinopril · metoprolol tartrate · furosemide
Spironolactone: stopped 4/14/2026
No SGLT2 inhibitor

Buried in 6 notes:
Echo 8/29/26: "LVEF 30%"
Problem list (2024): "HFmrEF (EF 45%)" ← copied-forward old value
Nephrology 4/14/26: "spironolactone discontinued due to hyperkalemia (K 5.9)"
Cardiology 6/10/26: "declines SGLT2 inhibitor: recurrent UTIs, cost"

Why this patient works

  • Each trap teaches one idea. The med list alone says "MRA gap" and "SGLT2i gap". Both are wrong: the reasons are in the notes. → tools
  • Metoprolol tartrate looks like a beta blocker but isn't evidence-based therapy for HFrEF. A model without the rule counts it. This was the single largest error by the direct LLMs in our study. → skills
  • The copied-forward EF 45% tests "most recent", which is exactly what clinicians know charts get wrong. → decomposition
  • The right answer is subtle: 1 real gap (beta blocker), 1 medical exception (MRA), 1 patient preference (SGLT2i). It's the abstract's message in one chart: find the gaps without counting documented exceptions as poor care.

Hand-written and fully synthetic, so no PHI or data-use questions. For the scale-up step we can generate 50–100 look-alike patients from the repo's synthetic fixture (just hfq-demo) or Synthea.

4 · Bruno's talk: five framings to choose from

Five minutes is about six slides. The brief (decomposition, skills, tools, orchestration) is good; the question is which metaphor makes it stick. Recommendation in green.

recommended

A · "Onboarding the new intern"

Clinicians already know how to make a capable newcomer useful. On day one you give an intern:

a clear job→ the task / goal
the department protocol→ instructions & skills files
an Epic login→ tools & data (FHIR, MCP)
a to-do list→ decomposition & orchestration
a sign-out template + attending→ structured output, evidence, oversight

Strength: zero jargon, maps 1:1 to the brief, hands off naturally to "trust" (the attending) and to the panel (entrustment). Risk: the intern metaphor over-humanises; one line should say "it's software: it doesn't learn from the shift unless we change the rulebook."

B · "The kitchen"

The model is a talented chef who has never been in this kitchen. Recipe card = skill. Knives and oven = tools. Mise en place = breaking the task down. The expediter at the pass = orchestrator and checker.

Strength: vivid, funny, memorable. Risk: one step removed from medicine, so it takes a translation step the intern version doesn't.

C · "Climb the ladder"

Build the agent one rung at a time and say what each rung adds: a rule over the med list → keyword search → one LLM call → an agent with tools → an agent with skills. Each rung fixes the error of the one below.

Strength: it is our study, so it's honest and concrete. Risk: overlaps Lovedeep's results talk and the live build. It might work better as the spine of the demo (it is, in the plan below).

D · "One patient, one minute"

The whole talk is a narrated replay of the agent reviewing Mrs. Delgado's chart, paused at each step to name the building block in play: "here it's planning… here it's using a tool… here the skill just changed its mind about metoprolol."

Strength: shows instead of tells; very concrete. Risk: needs a strong recap slide or the building blocks blur together. It combines well with A (A's structure, D's replay as the middle).

E · "Agents all the way down"

Open the hood live: a coding agent (Claude Code / pi) on stage is asked in plain English to build the abstraction agent, and the talk explains what it produced: the skill file, the tool list, the loop.

Strength: a genuine wow moment that shows where things are heading. Risk: live, slow and unpredictable in 5 minutes. Better as a 60-second recorded clip or a panel teaser.

Principles worth stealing for any framing

  • Let the model read; let the rules decide. The measure logic stays deterministic, and the AI only abstracts the facts, the way a human abstractor works against a CMS spec.
  • Small questions are checkable questions. "Is there a gap?" is hard to audit; "latest EF?" is easy.
  • No quote, no answer. An extracted value must come with text that appears in the note.
  • Same agent, two homes. It runs on a local open model inside the firewall (our PHI work) and on a cloud model for synthetic data (today's demo).

5 · Live build: options

Last year: install Ollama, run a small model in a shared Colab notebook. This year's proposal promises "off-the-shelf cloud tools, no local setup, follow along on your own device". These options can be combined; the recommended combination is at the end.

chosenphone-friendly

Build an agent (pipeline builder)

Lego-style blocks on a React Flow canvas: Task · Data · Tools · Rules · Model · Checks. Run it on Rosa, then on 100 synthetic patients scored against gold labels, and compare runs. Open →

supersededphone-friendly

D1 · The Agent Workbench

One web page, opened from a QR code. Mrs. Delgado's chart on the left, four switches in the middle (tools · skill · model · checker), and the agent's step-by-step trace and answer on the right. Each switch is one lesson. Attendees can edit the skill text on their phones and watch the answer change.

Live mode calls a model through a small proxy we host (one capped key, rate-limited, synthetic data only), so attendees never need an account. Replay mode plays recorded runs offline if the Wi-Fi fails. Prototype →

laptopcontinuity

D2 · "An agent in five cells" (Colab)

For people who liked last year's notebook: ① ask the model a question ② give it one tool ③ the loop (≈10 lines) ④ add a skill file ⑤ score it on 25 synthetic patients. Same patient, same steps as the Workbench, so both groups follow one story.

Model access: our proxy, or each person's free Gemini key (fiddly on the day: per-project quotas, key restrictions, not free in the UK/EU). google.colab.ai needs no key but may be Pro-only, so test it first.

no code

D3 · Build it in the tools you already have

Make the same agent with no code: a Claude Project / Custom GPT / Gemini Gem / Copilot agent, the skill file pasted in as instructions, Mrs. Delgado's notes uploaded as files. The message: you can prototype this tomorrow, on synthetic or approved data.

Most relatable for clinicians, and many health systems already license Copilot. Weakness: you can't see the loop, so it teaches less about what's under the hood.

interactiveunplugged

D4 · "You are the agent"

The room plays the agent. The screen shows the tool menu (search notes · open a note · med list · labs) and the audience votes on the next step. In about 6 votes they reach the answer, and they've just executed the loop themselves.

Needs nothing but a poll app. Built into the prototype as a mode. A strong opener for the 15 minutes, or a fallback if every network fails.

evaluation

D6 · Live leaderboard

Run all the strategies on 50 synthetic patients at once. Bars fill in live against clinician labels. The audience predicts the winner first. Then drill into one error and click through to its quote.

The repo can already do this on its synthetic fixture. Lovedeep's natural part of the demo: a practical evaluation framework people can reuse.

FHIR

D7 · Plug into a real FHIR server

Point the same agent at a public FHIR sandbox with synthetic patients and watch it make real API calls: GET MedicationRequest?patient=…. This is the same plug Epic exposes.

Strong interoperability message, and our fhir_llm_agent already does it. Raw JSON on screen is hard for clinicians to read, so translate each call into a plain-English line.

multimodal

D8 · The outside fax

Mrs. Delgado's latest echo arrives as a scanned outside-hospital fax (an image). The agent reads the image, finds "LVEF 30%", and the classification flips. That's "multimodal" in one honest, very familiar example.

Covers the proposal's "multimodal" promise without a gimmick. Cheap to add to D1.

orchestration

D9 · Close the loop

The finding becomes action: a second agent drafts a note to the PCP ("consider switching to metoprolol succinate or carvedilol") and a patient-friendly version. A human clicks Approve; nothing is sent automatically.

Shows orchestration (agents handing off), ties in Rosemary's talk, and sets up the panel's entrustment vote.

7 · What could go wrong on the day

Conference Wi-Fi

Every live call has a recorded replay one click away, and the Workbench runs from a single file. Rehearse fully offline once.

200 people, one API key

A proxy with per-device rate limits and a hard spend cap, using a cheap fast model. Phones get replay by default and live mode on request. Load-test with about 300 simulated clients.

The model does something new on stage

Use temperature 0, a pinned model version, and a rehearsed patient. If it goes off-script, that's a teaching moment for Lovedeep ("this is why we verify"), provided we've rehearsed what to say.

PHI / perception

Only synthetic patients, labelled as such on every screen. Say explicitly that the real study ran on a local model inside Yale's firewall.

Too much on screen

Use a projector mode at large type showing one panel at a time, and keep raw JSON off screen. Every tool call is shown as a plain sentence ("Searched notes for 'spironolactone': 1 hit").

Overselling

Say the numbers are preliminary (v0.6 reference built from strategy agreement plus adjudication) and show one failure on purpose.
